# What Orchestraitor should borrow from rig 0.44 (design ideas, native re-implementation)

**Basis:** `0025-a-rig-0.44.0-dependency-evaluation.md` (in-repo evidence) rejected rig as a dependency (2026-10-13) but flagged typed generation
options + per-provider refusal as a steal. This memo surveys rig `crates/rig-core/src` and
`rig-cassette`, `rig-agent` for everything else worth porting into our own code. Sources cited as
`rig:…` (rig) and our repo paths. [INFERENCE] where noted.

---

## Ranked steals

### 1. Typed generation options with per-provider refusal + dry-run check — **M, do first**

- **rig:** `completion/options.rs` — `GenerationOptions` (reasoning: Off|Effort(Minimal..Max)|Budget{tokens},
  cache, service_tier, verbosity, parallel_tool_calls, top_p, seed, stop) + `OnUnsupported::{Error,Ignore}`
  (default **Error**) + `UnsupportedOption{option, provider, model, reason}`. Refusal flows three ways:
  (a) per-wire mapping returns `Mapping::{Send, Omit, Unsupported}` (`completion/options/mapping.rs:64`);
  (b) per-provider typed extension options declare their own `unsupported()` list
  (`providers/anthropic/extension.rs:234`); (c) per-model catalog rules (`catalog/spec.rs:489` `request_rules`).
  `options/merge.rs:415` (`collect_refusals` thread-local) dry-runs a request and returns **all** refusals
  (`DynModel::check`, `driver/dyn_model.rs:224`). `OptionFields` has no `..`/default, so adding an option
  fails to compile in every wire until it answers for it.
- **reasoning specifics worth copying:** `providers/anthropic/options.rs:22` `claude_reasoning` —
  effort→`output_config.effort`, budget→`thinking.budget_tokens`, and typed refusals: no `minimal` level,
  "takes a budget, not an effort level" (and vice versa), budget ≥ 1024, budget < `max_tokens`,
  `temperature`-vs-`top_p` exclusivity, sampling-never-while-reasoning.
- **our slot today:** `provider-api/src/transport.rs` `ModelRequest` has flat fields + `reasoning:
  Option<ReasoningConfig{effort, budget_tokens}>` + **free-form `extensions` map**. `ReasoningEffort` is
  Low|Medium|High only. The neuralwatt wire maps effort (`provider-neuralwatt/src/wire.rs:264`) but
  **silently drops `budget_tokens`** — exactly the failure rig's policy forbids. `ProviderCapabilities`
  (`provider-api/src/capabilities.rs:45`) exists but nothing consults it at request-build time.
- **why now:** spec 30 §10.2 mandates typed extension fields for reasoning/caching/tool-choice/structured
  outputs; §9.29.3 forbids silent degradation ("visibly degrade — never silently fall back"); §9.45
  role presets set `effort`. Our refusal capability is currently one error variant
  (`CapabilityUnavailable`) checked by nobody.
- **what changes:** add `provider-api/src/options.rs`: `GenerationOptions`-style struct folded into
  `ModelRequest` (keep existing fields as the typed surface; move `extensions` behind a typed
  per-provider-options entry with a `"*"` shared section, per-protocol sections keyed by
  `ProviderProtocol`). Add `OptionRefusal{option, provider, model, reason}` to
  `ProviderTransportError` (new `UnsupportedOption` variant) and a `ProviderTransport::check(&ModelRequest)
  -> Result<(), Vec<OptionRefusal>>` default method dry-runs mapping; worker (`worker/src/model.rs`)
  calls `check` before the retry loop so a refusal is a typed, non-retried failure recorded in the
  call record. Each adapter answers via an exhaustive `OptionFields` destructure.

### 2. Content-block message model (thinking blocks, ordered, replayable) — **L**

- **rig:** `completion/message.rs` — `Message::Assistant(AssistantMessage{content: Vec<AssistantContent>,
  origin, stop})`; blocks `Text|ToolCall|Reasoning|Image|Opaque` **in provider order**; `Reasoning{text,
  redacted, native: Option<Native>}` (`message.rs:326`) keeps the provider-native item (e.g. thinking
  signature) for exact same-provider replay; `canonical()` strips native for cross-provider replay;
  `is_blank()`/replay-drop rules prevent sending empty or redacted reasoning back.
- **our slot today:** `ModelMessage{role, content: String}` (transport.rs:57) — text-only. Interleaved
  thinking cannot cross `ProviderTransport` at all; reasoning output is invisible to the TUI and lost
  from history. This is the blocker the eval itself identified (§3.5).
- **why now:** spec 30 §9.29.2(4) names "this GLM-5.2 adapter supports interleaved thinking" as adapter
  knowledge; §9.19.4 wants `reasoning_tokens` in the ledger (we have the count, not the surface).
- **what changes:** evolve `ModelMessage.content` from `String` to a content-block enum
  (`Text`, `Reasoning{text, redacted, native}`, `ToolCall`, `ToolResult`, later `Image`) — additive via a
  new `ModelContent` type plus `ModelMessage::text()` compat helper; keep `ModelEvent` folding in
  `worker/src/model.rs::collect_events` untouched initially (text path only). Native/replay discipline
  (canonical vs origin-pinned) rides along. Touches provider-api, worker, neuralwatt adapter, TUI.

### 3. Streaming tool-call argument deltas + partial JSON parsing — **M**

- **rig:** `streaming/event.rs` `StreamEvent::Arguments{part, json}` — raw argument **fragments** stream
  under a known tool name (a tool call `Start`s once its tool is named, `End`s with finalized content).
  `json_utils.rs:190` `parse_partial_arguments` → `parse_partial_object` + `repair_json` +
  `without_partial_escape`: longest valid object prefix of cut-off JSON, control-char repair, cut
  `\u` escapes. Contract: partial parse is **display-only**, never executed; the end event is truth.
- **our slot today:** `ModelEvent::ToolCall{id, name, arguments: Value}` fires only on complete parses;
  `provider-neuralwatt/src/stream.rs:135` tries `serde_json::from_str` **per delta fragment** and maps
  failure to `Value::Null` — streamed tool args are effectively lost, and no in-flight preview exists.
- **why now:** the eval's brief names "structured tool-arg streaming" as a spec-30 unlock; TUI surface
  for in-flight calls needs it, and Anthropic/GLM interleaved thinking + parallel calls will collide
  with single-complete-event framing anyway.
- **what changes:** add `ModelEvent::ToolCallStarted{id, name}`, `ToolCallArgsDelta{id, json: String}`,
  `ToolCallCompleted{id, name, arguments}` (keep `ToolCall` as an alias for a one-shot complete call
  during migration). Port `parse_partial_arguments` natively into `provider-api` (self-contained,
  ~120 lines, MIT-inspired) for TUI rendering; worker treats fragments as display-only and executes
  only `Completed` arguments. Neuralwatt `stream.rs` accumulates `function.arguments` fragments per
  tool-call index and emits deltas + one completion.

### 4. Retryable error classification on transport errors — **S, cheap high value**

- **rig:** `error.rs:115` `ErrorReport{kind, retryable, code, http_status, refusal, request_id,
  provider_response}` — `retryable` decided **once at conversion time** from the source's own
  classification (HTTP status / machine code), not by callers; `request_id` + provider response body
  preserved for the record.
- **our slot today:** `provider-api/src/error.rs:8` `RequestFailed{provider_id}` carries nothing;
  `worker/src/model.rs:184` retries **every** `RequestFailed` through the backoff budget — 400s and
  context-length errors burn the full retry budget and skew spend.
- **what changes:** widen `RequestFailed` with `retryable: bool`, `http_status: Option<u16>`,
  `provider_request_id: Option<String>` (no secrets); adapter sets them from the HTTP response; worker
  skips backoff for non-retryable classes and records `provider_request_id` in the call/ledger record
  (§9.19.4 `request_id` already exists there). No trait-shape change; variant field additions are the
  only break (this crate is internal).

### 5. Conformance scenario harness + unary/streamed raw parity — **M**

- **rig:** `test_utils/streaming_conformance.rs` — scenario tables drive **raw wire bytes** through the
  complete decode path and assert a written streaming contract ("an error is the stream's last item",
  "every part reaches the response exactly once"); per-provider fixtures supply frames; a scenario a
  wire can't spell returns `Skipped` cross-checked against a declared capability grid so skips can't
  masquerade as passes. `test_utils/raw_parity.rs` — the unary body and the rebuilt stream document of
  the same turn must decode **identically** after removing minted keys (ids, timestamps).
  Cassette replay with shape matching: `rig-cassette/src/http/shape.rs` (bodies keyed by structure, not
  values).
- **our slot today:** `orchestraitor-testkit/src/openai.rs` is a scripted mock server (captures requests,
  planned responses) — no raw-byte cassette files, no streamed-vs-unary parity, no skip accounting.
  Spec 30 §9.30.1 **mandates** recorded fixtures + event traces for OpenAI-compatible and
  Anthropic-compatible endpoints.
- **what changes:** add a `provider-api` (or testkit) `conformance` module: a scenario enum
  (error-terminates-stream, usage-before-error carries partial usage, tool-delta ordering, no-Completed
  fails closed) evaluated against any `ProviderTransport` adapter, with fixture files
  (`tests/fixtures/*.json` request/response byte pairs) per protocol family, explicit
  `ScenarioOutcome::Skipped` counted against the declared grid, and a raw-parity assertion for the
  neuralwatt OpenAI-compatible wire (unary vs SSE of the same turn). This becomes the §9.30.1 harness.

### 6. Structured-output fallback ladder with required-field validation — **M**

- **rig:** `structured_output.rs` — one strategy, three rungs: native structured outputs → synthetic
  `final_result` output tool (collision-numbered name, preamble augmentation, reprompt when the model
  answers as text) → prompted JSON with "ONLY a single JSON object" preamble and a reprompt naming the
  missing fields; `missing_required_fields(schema, args)` is the validation gate; `output_tool_callable`
  respects `ToolChoice::None`.
- **our slot today:** `ModelRequest.structured_output: Option<Value>` passes a schema; nothing validates
  the reply or reprompts. The §9.45.4 `structured_summary` + `output_contract` (fielded finish summary)
  needs exactly this ladder, since our first provider (OpenAI-compatible GLM-5.2) may not honor
  `response_format` at the user's tier (§9.29.1: metadata ≠ proof).
- **what changes:** put the ladder in `worker` (it owns call loops), not provider-api: a
  `StructuredOutputRunner` that (1) sends the request with schema, (2) validates top-level required
  fields natively, (3) falls back to tool-augmented and then prompted modes with at most N reprompts,
  recording which rung produced the answer in the call record. Note: rig's ladder is agent-loop code;
  we deliberately keep it out of the transport (spec: worker owns orchestration).

### 7. Part-framed stream events with order-checked transcripts — **S–M, fold into #3**

- **rig:** `streaming/event.rs` `Part(u32)` + `Start/…/End` framing with `End` carrying finalized
  content, and `Transcript::parse` validating a serialized event sequence is one the writer could have
  produced (start-once, grow-only-while-open, end-once).
- **why later/folded:** our boxed sync `Iterator` `ModelEventStream` can adopt Start/End framing via #3's
  event additions; the transcript *validator* is worth porting only when §9.30.1 event traces need
  replay validation (then it is the replay checker). Keep `Part` out until parallel tool calls or
  interleaved thinking actually require distinguishing concurrent parts — then it becomes required.

## Considered and cut

- **Catalog / model facts** (`rig-core/src/catalog/`) — collides with `orchestraitor-provider-meta`
  (live-first, provenance-stamped, §9.29 governance). Never.
- **USD cost auto-fill** (`catalog` pricing + `Usage::cost`) — fights §9.19.4's
  `monetary_cost_{measured,estimated,basis}` / subscription-utilization separation. Never.
- **Agent/tool loop, extractor, RAG, effect bus** (`rig-agent`, `tool/`, `vector_store/`) — spec assigns
  orchestration to `orchestraitor-worker` + Arbitraitor; rig has no receipt/ledger hook seam. Never.
- **Per-provider typed extension options as a general mechanism** (`completion/provider_options.rs`
  `ProviderExtension{PROVIDER, Options, Extras}`) — the *pattern* is right (typed, serialize-only,
  per-protocol sections) but as a full dyn-typed registry it's over-engineered for our 2-wire reality;
  absorb the idea into steal #1's typed options with `ProviderProtocol`-keyed sections.
- **`TaskBudget{total, remaining}` server-paced agent budget** (`providers/anthropic/extension.rs:299`) —
  [INFERENCE] interesting for Claude-family budget countdown, but our budget authority is the ledger +
  Arbitraitor caps; revisit only if an Anthropic wire lands and the ledger wants server-side pacing.
  Later at best.
- **Sorted canonical JSON helpers** (`json_utils.rs::to_canonical_string`) — only relevant for cassette
  determinism; adopt inside steal #5 if fixtures need stable digests.

## Suggested sequencing

1. #4 (S) + #1 (M) together — one PR family: typed options, refusal type, check, retry classification.
2. #3 + #7 framing (M) — event vocabulary first, neuralwatt accumulator second, TUI preview third.
3. #2 (L) — message blocks; do after #3 so Reasoning deltas and blocks land in one event-model revision.
4. #5 (M) — conformance harness once the event model is stable enough to pin in fixtures.
5. #6 (M) — structured-output ladder, rides §9.45.4 `structured_summary` work.
