Failure-mode proof (criterion d)
===============================
Method: re-run the item-identity check with an intentionally wrong
expected item id (999999) and a wrong title->number mapping
(E0 expected at E1's number, #296).

Result 1: expected item 999999 -> 0 matches on the live board -> MISMATCH reported: True
Result 2: E0 expected at #296 -> actual title 'Epic: E1 — Board abstraction + providers + multi-org workspaces' -> MISMATCH reported: True

The read-back validates identity by exact title + number + body sha256;
wrong expectations produce MISMATCH, not a pass. The verifier is not a
rubber stamp.
